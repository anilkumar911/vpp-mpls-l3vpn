Key Insight: Transport labels are identical — P routers (LSR1, LSR2) are completely VRF-unaware. They just swap the top label. VPN labels are different — this is what tells PE-SEC and PE2 which VRF to deliver into. Same GRE tunnel, same FW, same MPLS path — only the VPN label changes.

🔒 VRF Isolation — Cross-VRF Traffic Blocked

▼
$ docker exec host1 ping -c 2 -W 2 10.2.2.10 ← VRF 10 host → VRF 20 host PING 10.2.2.10 (10.2.2.10) 56(84) bytes of data. --- 10.2.2.10 ping statistics --- 2 packets transmitted, 0 received, 100% packet loss $ docker exec host3 ping -c 2 -W 2 10.1.2.10 ← VRF 20 host → VRF 10 host PING 10.1.2.10 (10.1.2.10) 56(84) bytes of data. --- 10.1.2.10 ping statistics --- 2 packets transmitted, 0 received, 100% packet loss ✓ VRF isolation confirmed — despite sharing the same MPLS core, GRE tunnel, and FW, VRF 10 and VRF 20 are completely isolated from each other. Why it works: • CE1 (VRF 10) has no route to 10.2.0.0/16 — it's in a different VRF on PE1 • Even if traffic reached PE1, VRF 10 FIB has no entry for 10.2.x.x • PE-SEC VPN labels (1100 vs 1200) deliver into separate FIBs • FW has separate VRF tables with separate default routes
